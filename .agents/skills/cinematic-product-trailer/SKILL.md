# Cinematic product trailers

Create a truthful, editable trailer that communicates one product idea through purposeful motion. Deliver the actual playable video when the user asks for a finished trailer, not only a storyboard or browser preview.

## Establish the production truth

Inspect the product, supplied assets, existing decisions, and current interface before writing claims. Use verified product language. Do not invent benefits, customers, performance figures, quotations, or capabilities.

Read [the production brief](references/production-brief.md) and write a project brief before production. Resolve missing details from available evidence when the choice is low risk. Ask only when a missing decision would materially change the story or delivery format.

## Choose a production method

Choose the smallest method that can execute the intended shot:

- Use deterministic motion graphics for typography, diagrams, interface reveals, screenshots, maps, and branded transitions.
- Use layered images with camera movement when approved images already carry the story.
- Use existing footage when it shows the product better than a reconstruction.
- Use editable 3D only when the concept needs an orbit, exploded view, material change, or travel through space.
- Use generated imagery or footage only when the request permits it and existing assets cannot cover the required shot. Label interpretive imagery when viewers could mistake it for evidence.

For Remotion work, use the installed official Remotion skills for current implementation details. Load only the relevant Remotion guidance, such as creation, markup, maps, multimedia, and rendering. Keep this skill responsible for the creative workflow and truth checks.

## Direct the story

Give the trailer one job. State the audience, the one idea viewers should remember, and one final action.

Map every scene to:

1. A time range.
2. A communication purpose.
3. A visible action over time.
4. Exact on-screen words.
5. Required assets and verified claims.
6. Sound or silence cues.

Describe visible action, not only mood. For example, specify that a route draws across the map, the camera follows it, and the scripture panel locks beside its destination. Do not substitute "make it epic" for direction.

For a roughly 30-second trailer, prefer this flexible arc:

- Opening: show the strongest result or visual hook.
- Premise: state the viewer's problem or the product's job.
- Transformation: demonstrate two or three connected capabilities.
- Payoff: show the larger value, not another feature list.
- Close: hold the product name and one clear action.

Keep text sparse. The video must remain understandable without sound. Use music and effects to strengthen the edit, not to carry missing meaning.

## Prove the direction before full production

Create representative stills for the hook, a feature scene, and the closing frame. Inspect hierarchy, safe margins, contrast, factual wording, source treatment, and likely viewing size.

Then render the hardest three-to-five-second moment. Choose the shot with the highest technical or visual risk, such as a map transition, interface transformation, or synchronized reveal. Verify the production method and art direction before building the complete timeline.

If the user requested autonomous completion, perform this review yourself and continue after fixing material defects. Do not stop merely to request approval unless a real creative choice remains unresolved.

## Build an editable project

Keep scenes in separate components or modules. Centralize approved text, colors, logos, assets, scene durations, and output dimensions. Keep text separate from artwork. Preserve source assets.

Use frame-driven animation. Avoid timing that depends on live CSS animation, network state, or nondeterministic page behavior. Give energetic moments readable holds. Use transitions only when they reveal a relationship or guide attention.

Keep claims and citations attached to the scenes that use them. Make limitations readable when they affect interpretation.

## Render and inspect

Read [the delivery checks](references/delivery-checks.md) before final rendering.

Export the requested format and keep the editable project. If the user asks for a finished trailer without specifying a format, prefer a broadly playable 1080p MP4 with audio and retain the editable source. Provide another format only when the environment cannot create MP4, and state the limitation.

Inspect the actual export from start to finish. Check representative frames and the full playback. Revise and render again when defects affect comprehension or polish.

Deliver:

- The playable final video.
- The editable source project.
- The brief and scene plan.
- A concise record of resolution, duration, audio, checks, and known limitations.
